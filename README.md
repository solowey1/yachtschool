# yachtschool — тренажёр МСС-65

Telegram-бот для изучения Международного свода сигналов 1965 года (МСС-65): сигнальные флаги, цифровые пенанты, заменяющие и ответный вымпелы, фонетический алфавит, азбука Морзе и однобуквенные сигналы. Архитектура спроектирована так, чтобы со временем легко добавлять другие разделы морских правил (МППСС, метеосигналы, флаги расцвечивания и т. д.).

## Что умеет

Главное меню — четыре раздела:

- 📖 **Справочник** — теория по разделам с возможностью провалиться в карточку конкретного флага/пенанта
- 🎯 **Обучение** — шесть тренажёров (см. ниже)
- 📊 **Статистика** — точность ответов в целом и по разделам
- ⚙️ **Настройки** — язык интерфейса, количество вопросов в день, время отправки

### Тренажёры

| Раздел | Что спрашивают | Количество записей |
|---|---|---|
| 🚩 Флаги | флаг → буква, буква → флаг (сетка 2×2 из 4 вариантов) | A–Z |
| 📛 Названия букв (фонетика) | буква ↔ название (Альфа / Браво / Чарли …) | A–Z |
| 📡 Азбука Морзе | буква ↔ комбинация точек/тире | A–Z + 0–9 |
| 📜 Однобуквенные сигналы | флаг ↔ значение как самостоятельного сообщения | A–Z |
| 🎏 Цифровые и служебные флаги | пенант ↔ обозначение, цифра ↔ Морзе | 0–9, 3 заменяющих, ответный |
| 🔤 Буквы (смешанный режим) | сборная солянка из буквенных тренажёров | A–Z |

**В фонетике дистракторы не «случайные слова», а кураторские «созвучные ловушки» — все начинаются на ту же букву, что и правильный ответ.** Например, для V (Виктор) вариантами могут быть Виски, Виктория, Вектор, Винчестер. Для К/Q и V/W в дистракторы подкладывается реальная парная МСС-буква (Кило ↔ Квебек, Виктор ↔ Виски).

### Ежедневная рассылка

По умолчанию каждый день в **17:00 по Москве (=14:00 UTC)** бот присылает 5 вопросов: 4 ранее не задававшихся комбинации `(тренажёр, буква)` плюс 1 на повторение — недавно отвеченный неправильно вопрос (или ещё одна свежая позиция, если ошибок не было). Защита от дублей через `daily_deliveries` (ключ — `user × UTC-дата`).

Каждый пользователь в разделе **Настройки** может перебить:

- 🌐 **Язык** интерфейса — кнопка появляется автоматически, когда в `app/i18n/locales/` оказывается ≥2 файлов (сейчас один `ru.json`, кнопка скрыта)
- 🔢 **Количество вопросов** — пресеты 1 / 3 / 5 / 7 / 10
- 🕒 **Время отправки** — 24 часа по UTC (сетка 4×6)

Пользовательские настройки всегда в UTC; env-default остаётся MSK для удобства администратора. Шедулер тикает каждую минуту по UTC и для каждого активного пользователя проверяет, совпадает ли текущая минута с его эффективным временем.

### Inline-режим

Бот можно вызывать **из любого чата** через `@<имя_бота>` — без необходимости заходить в личку с ним. Запрос ищется по русскому имени, английскому NATO-имени, букве/цифре и тексту значения сигнала:

| Ввод | Что покажет |
|---|---|
| `@bot` (пусто) | все 40 флагов в каноническом порядке |
| `@bot b` или `@bot B` | флаг буквы B |
| `@bot 5` | цифровой пенант 5 |
| `@bot bravo` / `@bot браво` | флаг B (Браво) |
| `@bot whiskey` / `@bot виски` | флаг W |
| `@bot помощь` | V (Виктор) и W (Виски) |
| `@bot опас` | B, J, U (вокруг «опасный груз»/«опасность») |
| `@bot nadazero` | пенант 0 |
| `@bot ответ` | ответный вымпел |

**Авто-бутстрап:** при первом `/start` в личке с ботом, если кеш `file_id` ещё пустой, бот разово пришлёт вам все 40 флагов и сохранит их идентификаторы в БД. Это техническое ограничение Telegram (для inline-результатов нельзя использовать локальные файлы, нужны либо публичные URL, либо уже загруженные `file_id`). После этого inline работает мгновенно из любого чата, кеш переживает рестарты контейнера.

Если нужно перезалить (например, файлы устарели или вы хотите принудительно обновить графику) — выполните `/preload_inline` в личке. Команда загружает только недостающие коды; для полной перезаливки очистите таблицу `inline_media_cache` руками.

**Включение inline у бота** в `@BotFather`:
1. Откройте `@BotFather` → `/setinline`
2. Выберите вашего бота
3. Задайте placeholder (например, `буква, цифра или название`)

### Редактирование сообщений

Внутри сессии обучения **одно и то же сообщение** редактируется на каждом шаге: вопрос → результат → следующий вопрос. Все вопросы — фото с подписью (для текстовых тренажёров рендерятся карточки), что снимает ограничение Telegram «нельзя поменять тип сообщения». На границах меню↔квиз (текст↔фото) происходит delete+send одной транзакцией — это неустранимо в Bot API. Ежедневная рассылка идёт пятью отдельными сообщениями (так пользователь может пройти их «своим темпом»); после ответа на ежедневный вопрос «Следующий» не показывается — следующий уже в чате ниже.

## Архитектура

```
app/
├── bot/                  # aiogram-маршрутизация, middleware, клавиатуры, callbacks
│   └── handlers/         #   start / menu / quiz / stats / settings / reference
├── db/                   # модели и сессия SQLAlchemy 2.x (async)
├── i18n/                 # JSON-локали + lookup-движок (t(), t_list())
├── repositories/         # CRUD/запросы к Postgres
├── services/             # picker, quiz_engine, scheduler, user_settings
└── training/             # фреймворк тренажёров
    ├── base.py           #   абстракции Trainer / Topic / Question
    ├── registry.py       #   глобальный реестр (subject → topic → trainer)
    └── mcs65/            #   первый предмет — МСС-65
        ├── data.py       #     буквы A–Z + Морзе
        ├── pennants.py   #     0–9, S1/S2/S3, AP
        ├── flag_renderer.py    # рендер 26 буквенных флагов + текстовых карточек
        ├── pennant_renderer.py # рендер 14 пенантов
        └── trainers.py   #     12 тренажёров + регистрация тем
```

Добавление нового раздела (например, МППСС-72) — это новый каталог в `app/training/<subject>/` с собственным набором тренажёров; они регистрируются в реестре через `register()` и автоматически появляются в меню. Никаких изменений в коде бота не требуется.

Тексты, названия букв, значения сигналов, дистракторы для фонетики, тексты справочника — всё в `app/i18n/locales/ru.json` под точечными ключами. Чтобы добавить английский, положите `en.json` рядом — переводчик подхватит его автоматически и в меню появится переключатель языка.

## Запуск

### Через Docker Compose

1. Скопируйте `.env.example` в `.env` и заполните `BOT_TOKEN`:

   ```bash
   cp .env.example .env
   # отредактируйте BOT_TOKEN
   ```

2. Поднимите всё:

   ```bash
   docker compose up -d --build
   ```

   Compose поднимет Postgres 16 + бот. При старте контейнера: накатываются миграции Alembic, рендерятся флаги и пенанты в `assets/flags/` (кешируются между запусками).

3. Логи:

   ```bash
   docker compose logs -f bot
   ```

### Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOT_TOKEN` | — | токен бота от `@BotFather` |
| `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` | `yachtschool` | креды Postgres |
| `DAILY_DELIVERY_TIME` | `17:00` | дефолтное время рассылки (часы:минуты) |
| `DAILY_DELIVERY_TIMEZONE` | `Europe/Moscow` | таймзона для дефолтного времени |
| `DAILY_QUESTIONS_COUNT` | `5` | дефолтное количество вопросов в день |
| `DEFAULT_LANGUAGE` | `ru` | код локали по умолчанию |
| `LOG_LEVEL` | `INFO` | уровень логирования |

Эти значения — **дефолты для всех пользователей**. Каждый пользователь может перебить количество и время через раздел «⚙️ Настройки»; в этом случае его настройки хранятся в UTC и приоритетнее env.

### Nginx

Бот работает в режиме long polling и не требует входящего HTTP — порты бота не публикуются наружу. Если когда-нибудь понадобится webhook, добавьте сервис `nginx` снаружи compose.

## База данных

Таблицы:

- **`users`** — Telegram-пользователи: язык, флаг ежедневной рассылки, пользовательские override-ы (`delivery_time_utc`, `daily_questions_count` — оба nullable, NULL = использовать env-default)
- **`question_answers`** — каждый ответ; идентичность вопроса = `(trainer_key, entry_code)`; индексы для быстрого поиска «не присылавшихся» и «отвеченных неправильно»
- **`daily_deliveries`** — отметки доставленных пятёрок (ключ `user_id × UTC-дата`, защита от дублей при перезапуске или повторном тике)
- **`inline_media_cache`** — кеш `file_id` для inline-режима: `code → telegram file_id`, заполняется командой `/preload_inline` (см. секцию «Inline-режим»)

Миграции живут в `alembic/versions/` и накатываются автоматически при старте бота. Создать новую:

```bash
docker compose exec bot alembic revision --autogenerate -m "your_change"
```

## Локаль и контент

Все пользовательские тексты — в `app/i18n/locales/<lang>.json`. Структура ключей:

- `common.*`, `start.*`, `menu.*`, `quiz.*`, `daily.*`, `stats.*`, `settings.*` — UI
- `reference.*` — статьи справочника + шаблоны детальных карточек
- `mcs65.name.*` — фонетические имена букв
- `mcs65.name_distractors.*` — кураторские «созвучные ловушки» для каждой буквы (JSON-массивы)
- `mcs65.meaning.*` — значения однобуквенных сигналов
- `mcs65.pennant_name.*` / `mcs65.pennant_label.*` / `mcs65.pennant_meaning.*` — нелитерные флаги

`t(key, lang, **kwargs)` достаёт строку с подстановкой плейсхолдеров; `t_list(key, lang)` — массив (используется для дистракторов фонетики).

## Стек

Python 3.12, aiogram 3.13, SQLAlchemy 2.x (async + asyncpg), Alembic, APScheduler, Pillow, pydantic 2, pytz, structlog. PostgreSQL 16 в compose.

## Лицензия и источники

Тексты однобуквенных сигналов, названия букв и фонетического алфавита, описания заменяющих и ответного вымпелов адаптированы из МСС-65 (Международный свод сигналов, ред. 1965 г.). Графика флагов и пенантов отрисовывается программно по описаниям из свода — это MVP-приближения, для прод-использования можно заменить на SVG-ассеты, точечно подменив `flag_renderer.py` / `pennant_renderer.py` (остальной код менять не потребуется).
